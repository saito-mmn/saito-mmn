## Who I am

金融・不動産領域の実務経験をバックグラウンドとして、データエンジニアリング・データ分析に取り組んでいます。
銀行での担保評価、FASでの資産評価レビュー、金融データプロダクトのETL・運用自動化を経験してきました。

評価・分析業務経験を通じて、説明可能な意思決定には、その前提となるデータの収集・構造化・品質管理が不可欠だと感じ、データエンジニアリング領域へ軸足を移しました。

現在は、曖昧な業務仕様や未整備なデータを構造化し、再現可能なデータ処理・分析基盤へ落とし込むことをテーマに個人開発を行っています。

業務課題からデータ処理を設計することと、データや技術から新しい活用可能性を見つけることの両方を重視し、最終的に意思決定や業務価値へ接続することを意識しています。

## Featured Project

### Hotel Supply & Demand ETL

**ホテル担保評価の実務課題を題材にした、公的統計の自動更新型データパイプライン**

[Repository](https://github.com/saito-mmn/hotel-supply-demand-etl) · [Live Demo](https://saito-mmn.github.io/hotel-supply-demand-etl/)

#### Why

銀行でホテルの担保評価を担当する中で、個別ホテルの収益性だけでなく、所在地の宿泊需要、客室稼働率、供給環境などを継続的に確認する必要がありました。

一方で、公的統計は複数のExcelに分散し、年度や公表区分によって構造も異なるため、必要なデータを都度収集・加工する負荷が大きいという課題がありました。

そこで、**「分析のたびにデータを集め直す」のではなく、継続的に更新・再利用できる形でデータを整備する仕組み**を作ることを目的に、このプロジェクトを開発しました。

#### What

観光庁・e-Statの「宿泊旅行統計調査」を取得・正規化し、全国・都道府県・市区町村の宿泊市場を継続的に確認できるデータ基盤と分析レポートを構築しています。

主に以下を扱います。

- 宿泊需要
- 客室稼働率
- 外国人宿泊者比率
- 調査対象施設数
- 季節変動や需給動向

担保価値や融資判断を自動化するものではなく、**評価担当者が市場環境を確認するための一次資料を継続的に生成すること**を目的としています。

#### How

```text
Source
  ↓
ETL
  ↓
Data Quality
  ↓
SQLite
  ↓
Analytics Report
```

継続運用を前提として、以下も実装しています。

公式データの新規公表・訂正検知
URL・公表日・取得日時・SHA-256によるデータ来歴管理
構造の異なるExcelの共通スキーマ化
欠損値・件数・値範囲・整合性の品質検証
一時DB・一時レポートを利用した安全な更新
pytestによる自動テスト
GitHub Actionsによる更新・CI
GitHub Pagesへの自動デプロイ
